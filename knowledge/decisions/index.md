# Decision

- [Make OKF Knowledge Harvesting the First Pro Slice](make-okf-knowledge-harvesting-the-first-pro-slice.md) - Use repo-local OKF knowledge harvesting as the first narrow Pro workflow instead of beginning with a broader search or skills-sync feature.
- [Reuse the analysis provider selector for implementation commands](reuse-the-analysis-provider-selector-for-implementation.md) - Use the analysis provider picker for implementation so users select the actual model or agent that performs the work.
- [Route Pro Capabilities Through the Single Extension Install](route-pro-capabilities-through-the-single-extension-install.md) - Ship Pro capabilities as companion functionality loaded by the single customer-facing extension install.
- [Ship only Pro package.json and dist/index.js in the VSIX](ship-only-pro-package-json-and-dist-index-js-in-the-vsix.md) - Include only the Pro manifest and compiled entrypoint so runtime resolution works without shipping source maps or unrelated artifacts.
- [Use GitHub Packages for CI-Safe Pro Distribution](use-github-packages-for-ci-safe-pro-distribution.md) - Publish the Pro package to GitHub Packages so CI installs it without a local sibling-repository dependency.
- [Use one selected execution provider for all eligible `.chat` sessions](use-one-selected-execution-provider-for-all-eligible-chat.md) - Let users choose the execution provider for analysis while keeping every eligible session in the workspace’s `.chat` folders in scope.
